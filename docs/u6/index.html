Conceito fundamental

Dois problemas diferentes

🔑 Autenticação — quem é você?

Verificar que o usuário é quem diz ser. Usuário + senha no banco de dados. Se bater, provamos identidade.

Exemplo: "Você digitou a senha certa para o e-mail joao@email.com"

🛡️ Autorização — o que você pode?

Verificar que o usuário autenticado tem permissão para a ação. Um motorista não pode excluir veículos.

Exemplo: "Você está autenticado, mas não tem perfil de admin"

Conceito — JWT

O crachá digital

JSON Web Token é um token assinado que o servidor emite após o login. O cliente o guarda e envia em cada requisição. O servidor verifica a assinatura — sem precisar consultar o banco novamente.

routes/authRoutes.js — login // 1. usuário envia e-mail e senha
router.post('/login', async (req, res) => {
  const { email, senha } = req.body;

  // 2. busca no banco e compara com bcrypt
  const usuario = await buscarPorEmail(email);
  const ok = await bcrypt.compare(senha, usuario.senha_hash);

  if (!ok) return res.status(401).json({ erro: 'Credenciais inválidas' });

  // 3. emite o token JWT
  const token = jwt.sign({ userId: usuario.id }, process.env.JWT_SECRET);
  res.json({ token });
});
Conceito — Middleware de autenticação

O guarda que fica entre a rota e o controller

Um middleware é uma função que roda entre a requisição e o handler final. O middleware de auth verifica o token antes de deixar a requisição chegar no controller.

🌐
Requisição chega
GET /api/v1/veiculos com Authorization: Bearer <token>

Só chega aqui quem passou pela verificação
middlewares/auth.js function verificaToken(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];

  if (!token) return res.status(401).json({ erro: 'Token ausente' });

  try {
    const payload = jwt.verify(token, process.env.JWT_SECRET);
    req.usuario = payload; // disponível no controller
    next(); // passa para o próximo
  } catch {
    res.status(401).json({ erro: 'Token inválido' });
  }
}
