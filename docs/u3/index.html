Conceito — HTTP

Uma conversa entre dois lados

HTTP é o protocolo que governa a comunicação entre navegador e servidor. Cada interação é uma troca: o cliente envia uma requisição, o servidor devolve uma resposta.

Cliente
Navegador
GET /api/v1/veiculos →
⇄
← 200 OK + JSON
Servidor
Node.js

Toda requisição carrega: método (GET, POST...), URL (qual recurso), headers (metadados) e, opcionalmente, body (dados enviados).

Conceito — Node.js sem framework

O servidor na sua forma mais crua

Com o módulo http nativo do Node.js, criamos um servidor que recebe cada requisição e decide manualmente o que fazer.

$ node servidor.js
Servidor rodando em http://localhost:3000
servidor.js const http = require('http'); // módulo nativo do Node

const servidor = http.createServer((req, res) => {

  // req.method → qual verbo HTTP foi usado
  // req.url → qual URL foi acessada

  if (req.method === 'GET' && req.url === '/api/v1/veiculos') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify([
      { placa: 'ABC-1234', modelo: 'Fiat Ducato' }
    ]));

  } else {
    res.writeHead(404);
    res.end(JSON.stringify({ erro: 'Rota não encontrada' }));
  }
});

servidor.listen(3000);
A dor que essa etapa causa (de propósito)

Por que isso é difícil — e por que precisa ser

😰 O problema

Adicionar POST requer ler o body manualmente com eventos. Capturar /veiculos/ABC-1234 exige fatiar strings. Com 4 entidades × 5 verbos = 20 rotas no mesmo if/else.

✅ A solução (etapa 4)

Express nasceu exatamente para resolver essa dor. Ao sentir o problema aqui, você vai entender por que o Express existe — não só como usá-lo.
servidor.js — lendo body de um POST (trabalhoso) if (req.method === 'POST' && req.url === '/api/v1/veiculos') {
  let body = '';

  // body chega em pedaços (chunks) — temos que montar
  req.on('data', chunk => { body += chunk; });

  req.on('end', () => {
    const dados = JSON.parse(body);
    // agora sim podemos usar os dados...
  });
}
⚠️ Observe: o Express vai fazer tudo isso automaticamente com express.json(). Mas só faz sentido apreciar isso depois de ter sentido a dificuldade aqui.

Os objetos req e res

o que temos em cada requisição // req — o que o CLIENTE enviou
req.method // 'GET', 'POST', 'PUT', 'DELETE'
req.url // '/api/v1/veiculos'
req.headers // { 'content-type': 'application/json', ... }

// res — o que o SERVIDOR vai devolver
res.writeHead(200, { 'Content-Type': 'application/json' });
res.end(conteudo); // envia e fecha a conexão
✅ O que aprendemos: módulo http, createServer, req.method, req.url, res.writeHead, res.end, JSON.stringify, eventos de stream (data/end), e o ciclo completo de uma requisição HTTP.
